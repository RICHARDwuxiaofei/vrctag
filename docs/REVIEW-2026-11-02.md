## F-01：同一网格内的反向独立壳体被校验器接受

**建议优先级 P2，状态 OPEN；确定性合成复现。**

位置：[web/src/model.ts 的 validateMesh](../web/src/model.ts)、[Python validate_3mf.py](../studio/scripts/validate_3mf.py)。两者按整份 part 累加有向体积。闭合边只能保证每个壳体内部定向一致，不能证明每个外壳方向向外。

复现：两个不接触的四面体，较大壳体正向、较小壳体反向。总有向体积约 `1.1666666667 mm³`，异常边 0、退化面 0，于是返回 `valid: true`。`export3mf` 也会接受；独立 Python 检查器同样接受。

- [完整顶点及三角形构造](../web/tests/review-matrix.ts)的 `tetra` 常量。
- [故意无效的诊断文件 synthetic-inward-shell.3mf](../studio/evidence/review-2026-11-02/synthetic-inward-shell.3mf)，**不是可打印名牌示例，不要拿它打印**。
- 矩阵中 `mesh-disconnected-inward-shell` 的期望是 reject，实际 accept，记录 FAIL。

这证明当前检查器的能力边界；**没有证据表明本次 30 个正常 UI 配置输出都含反向壳体**。后续审核应检查连通分量、壳体包含关系与每个分量的预期方向；不能对有合法空腔的通用网格简单要求每个分量体积都为正。对本项目互不相交的实心字形外壳可明确约束。

## F-02：损坏头像会错误阻止纯实体 3MF 导出

**建议优先级 P2，状态 OPEN；真实浏览器已复现。**

位置：[web/src/main.tsx](../web/src/main.tsx)的 `loadAvatar` 与全局 `error` / `valid`。头像解码错误和打印/模型错误共用同一个错误状态；`valid` 要求 `!error`，于是图片预览错误也会禁用打印导出。

复现：

1. 使用正常名字、状态及 Pronouns，确认“网格检查通过”。
2. 点击头像上传，选择本报告附带的 [invalid.png](../studio/evidence/review-2026-11-02/invalid.png)（故意把普通文本命名成 .png）。
3. 页面提示“无法读取这张图片，请使用其他图片。”，3MF 按钮同时被禁用；打印几何并未因此改变。
4. 点击重置可恢复。这是恢复手段，不是缺陷已修复。

[真实错误截图](../studio/evidence/review-2026-11-02/browser-invalid-avatar.jpg)。建议将头像错误与建模/导出错误分开，使无法解码的图片不影响有效实体导出，并测试错误清理/重试路径。

## V-01：近景参考显示比例仍需视觉调整

**状态 PARTIAL；不是本轮已经实施的修改。** 用户补充说明：胶囊外面的金边代表正在说话，不能当作默认好友实体外框。好友名字金色与说话提示要分开。

按聊天中的近景图粗略测量（受截图透视影响，非精确规范）：主体宽高比约 3.0∶1，当前 120/38≈3.16；主名字高度约占主体 25%，当前 10/38≈26%，基本接近。头像图区参考约占高度 75–80%，当前 24/38≈63%；状态点约 18–20%，当前 5/38≈13%；第二行约 14–16%，当前 4/38≈10.5%；头像框当前 2 mm 偏厚。

待审核建议：头像图直径约 29–30 mm、细框约 0.8–1 mm、点直径约 7 mm、小字约 5–5.5 mm。调整会影响几何布局与碰撞，需一起验证头像/点的接合、文字间距和实体重叠，不能只改预览比例。用户未要求这轮直接改模型，因此尚未实施。第三方参考截图没有复制进 Git 仓库；审核者需要用户另行提供截图时，不应从本报告假装获得精确像素证据。截图第二行内容本身也不能证明字段一定是 Pronouns。
